# 安全与执行边界

Docker 任务默认禁用网络、移除 Linux capabilities、启用 `no-new-privileges`，使用只读且限制容量的临时文件系统，并限制 CPU、内存和进程数。任务只获得一个可写绑定挂载：它的分离式 Git Worktree。内置运行镜像使用非特权用户，执行器还会传入明确的非 root 数字用户。在 Linux 上，它使用宿主机的非 root UID/GID，确保绑定挂载文件仍可写；root 宿主机和 Windows 使用 `1000:1000`。

文件工具会在访问前解析路径，并拒绝越出 Worktree 的路径穿越。默认禁止修改 `.git`、`.repofix` 和工作流定义。最终验证也会拒绝修改禁止路径或文件数量过多的补丁。

这是为受控代码任务设计的实用边界。Docker 容器不是能够抵御恶意内核或 Docker 守护进程漏洞的绝对多租户安全边界。本地执行器会直接运行命令，只适用于可信测试夹具和开发场景。凭据应保留在控制器进程中，绝不会注入任务容器。

浏览器控制台绑定到 `127.0.0.1`，不提供远程监听选项。已保存的 API 密钥在 API 响应中会被隐藏。Agent 获得访问权限之前，普通文件夹快照会排除 `.env`、虚拟环境、依赖目录和版本控制元数据。
